# Trackr – CLAUDE.md

Android app (Kotlin/Compose/M3) for tracking movies, TV and anime with friends. Package `com.trackr.app`, minSdk 26, target/compile 35.

## Environment (headless VPS)
- JDK 17, Android SDK at `/opt/android-sdk` (platform 35, build-tools 35.0.0 + 34), Gradle wrapper 8.10.2.
- `export ANDROID_HOME=/opt/android-sdk` (also in ~/.bashrc). `local.properties` has `sdk.dir` + secrets.
- Secrets live in `local.properties` (gitignored): TMDB_READ_TOKEN, SUPABASE_URL, SUPABASE_ANON_KEY, GOOGLE_WEB_CLIENT_ID → BuildConfig. Never print/commit them.
- Single keystore `trackr.keystore` + `keystore.properties` (both gitignored) signs debug AND release so SHA-1 is stable.
- Stitch design export is unzipped in `stitch/` (gitignored); tokens in `stitch/**/cinematic_dark/DESIGN.md`.
- AniList needs no auth (public GraphQL); the AniList client id/secret are not used.

## Stack
Compose + M3, single activity, MVVM + Hilt, Flow, Navigation Compose, supabase-kt (auth, postgrest), Retrofit+kotlinx.serialization (TMDB v3, Bearer v4 token), Apollo Kotlin (AniList), Coil, Room, WorkManager, Credential Manager.

## Layout
`app/src/main/java/com/trackr/app/{data(remote,local,repository),domain,ui(theme,navigation,components,screens)}`

## Decisions
- Dark default (Cinematic Dark palette), light + system supported via `ThemeMode`.
- Inter variable font bundled in res/font (no GMS font provider).
- Release APK renamed to `trackr-release.apk`.

## Supabase
- Tables: profiles (extra col `username_set` = false until user picks a username), list_entries (+ `completed_at`, migration 20261005000001 — apply before shipping a build that syncs it), friendships; view `friend_activity` (security_invoker). `are_friends(a,b)` security-definer helper only answers for the caller.
- Signup trigger builds profile from Google name/avatar. Anon role has no table access.
- Social (migration 20261005000002, test supabase/tests/social_test.sql → SOCIAL_TESTS_PASSED): entry_reactions (5 fixed emoji) + entry_comments on list_entries — visible/writable exactly when the entry is (policies use `exists(select … from list_entries)`, so list_entries RLS decides); author or entry owner deletes comments. recommendations between accepted friends (unique per pair+title); recipient may only update `seen` (column grant; table grants are revoked first because Supabase default privileges grant everything).
- Live project (xxmosmbtgojzhvzgnxuf) has every migration in supabase/migrations applied: list_entries_notify, list_entries_completed_at, social_reactions and shared_lists via the Supabase connector; delete_account by hand in the SQL editor (the connector's apply_migration timed out on it), so it isn't in the project's migration history. Security advisor: the remaining SECURITY DEFINER warnings (are_friends, is_list_member, delete_account) are intentional.
- Shared lists (migration 20261005000003, test supabase/tests/shared_lists_test.sql → SHARED_LISTS_TESTS_PASSED): shared_lists / shared_list_members / shared_list_items. `is_list_member(list)` security-definer helper (caller-only) avoids policy recursion; a trigger makes the owner the first member; the lists SELECT policy also allows owner_id = caller because INSERT … RETURNING is checked before that AFTER trigger. Only the owner adds members (friends only) or removes others; members leave; owner deletes. Only `name` is updatable.
- `delete_account()` (security definer, authenticated only) deletes the caller's auth user; cascades remove profile, list_entries, friendships. Settings → Delete account calls it, then wipes the device like sign-out.
